=====================================================================
 LOAD TEST - FAKESTORE API LOGIN SERVICE (k6)
=====================================================================

1. OBJECTIVE
---------------------------------------------------------------------
Load test of the login service:

    POST https://fakestoreapi.com/auth/login
    Content-Type: application/json
    { "username": "<user>", "password": "<passwd>" }

Acceptance criteria:
  - Throughput: the scenario must reach at least 20 TPS.
  - Response time: maximum 1.5 seconds (1500 ms).
  - Error rate: lower than 3% of all requests.


2. TECHNOLOGIES AND VERSIONS
---------------------------------------------------------------------
  - k6 (Grafana Labs) ........ v2.4.0 (go1.26.11, windows/amd64)
  - k6 jslib k6-summary ...... 0.1.0 (loaded from https://jslib.k6.io,
                               requires internet access)
  - Operating system ......... Windows 11 (10.0.26200) - also runs on
                               Linux/macOS with the same commands
  - Package manager .......... winget (Windows Package Manager)
  - Git ...................... 2.56.0 (only to clone the repository)

No Node.js, npm or other runtime is required: k6 runs the JavaScript
script with its own embedded engine.


3. PROJECT STRUCTURE
---------------------------------------------------------------------
  LoadTestLogin/
  |-- data/
  |   `-- users.csv                 Test data (user,passwd)
  |-- scripts/
  |   `-- login-load-test.js        k6 script (scenario + validations)
  |-- results/                      Reports generated by each run
  |   |-- summary.txt / .json       Last run (summary)
  |   |-- summary-20tps.txt / .json Official run at 20 TPS
  |   `-- summary-40tps.txt / .json Additional headroom run at 40 TPS
  |-- readme.txt                    This file
  `-- conclusiones.txt              Findings and conclusions


4. STEP-BY-STEP EXECUTION
---------------------------------------------------------------------
Step 1 - Install k6 v2.4.0

  Windows (winget):
      winget install --id GrafanaLabs.k6 -e --version 2.4.0

  Windows (MSI, manual):
      https://github.com/grafana/k6/releases/download/v2.4.0/k6-v2.4.0-windows-amd64.msi

  macOS:
      brew install k6

  Linux (Debian/Ubuntu): see https://grafana.com/docs/k6/latest/set-up/install-k6/

  Docker (alternative, no installation):
      docker run --rm -v "%cd%:/work" -w /work grafana/k6:2.4.0 run scripts/login-load-test.js

Step 2 - Verify the installation (open a NEW terminal so PATH is refreshed)

      k6 version
      -> k6.exe v2.4.0 ...

  If "k6" is not recognized, use the full path:
      "C:\Program Files\k6\k6.exe" version

Step 3 - Clone / open the repository and move to its root folder

      cd LoadTestLogin

  IMPORTANT: always run k6 from the repository root, because the
  reports are written to the relative folder "results/".

Step 4 - (Optional) Review / edit the test data in data/users.csv

      user,passwd
      donero,ewedon
      kevinryan,kev02937@
      johnd,m38rmF$
      derek,jklg*_56
      mor_2314,83r5^_

  The script reads the file once (SharedArray) and assigns the
  credentials in round-robin to every request.

Step 5 - (Optional) Smoke test: verify the script with low load

      k6 run -e TARGET_TPS=2 -e HOLD_DURATION=10s scripts/login-load-test.js

Step 6 - Run the load test (official scenario, 20 TPS)

      k6 run scripts/login-load-test.js

  Scenario (executor "ramping-arrival-rate", open model):
      - Ramp-up   : 1  -> 20 TPS in 30 s
      - Steady    : 20 TPS during 2 min
      - Ramp-down : 20 -> 0  TPS in 15 s
      Total duration ~2 min 45 s, ~2,865 requests.
      Each iteration sends exactly 1 login request (1 iteration = 1 TPS).

Step 7 - Read the results

  - Console: k6 end-of-test summary. Every threshold appears with
    a check mark (passed) or a cross (failed).
  - Files: results/summary.txt (text) and results/summary.json (raw).
  - Exit code: 0 = all thresholds passed, 99 = some threshold failed
    (useful for CI/CD pipelines).

      Windows PowerShell : echo $LASTEXITCODE
      Windows CMD        : echo %ERRORLEVEL%
      Linux/macOS        : echo $?


5. CONFIGURABLE PARAMETERS (-e KEY=value)
---------------------------------------------------------------------
  BASE_URL        Base URL of the API     (default https://fakestoreapi.com)
  TARGET_TPS      TPS of the steady state (default 20)
  HOLD_DURATION   Steady-state duration   (default 2m)

  Example - stress/headroom test at 40 TPS for 1 minute:
      k6 run -e TARGET_TPS=40 -e HOLD_DURATION=1m scripts/login-load-test.js


6. VALIDATIONS IMPLEMENTED
---------------------------------------------------------------------
Thresholds (they make the test PASS/FAIL):
  - http_req_duration : max < 1500 ms and p(95) < 1500 ms
  - http_req_failed   : rate < 3%   (HTTP errors / timeouts)
  - login_errors      : rate < 3%   (custom functional error rate)
  - checks            : rate > 97%

Checks per request:
  - status is 200/201
  - response body contains a non-empty "token"
  - response time <= 1500 ms
